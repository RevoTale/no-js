# Migrate v2.1.0 to v2.1.1: Correct Go Module Path

The existing v2.0.0 and v2.1.0 Git tags used an unversioned Go module path.
Go rejects those tags because a v2 module must end in `/v2`. Applications using
an unversioned pseudo-version or a local checkout must migrate their imports
before pinning v2.1.1. Existing tags remain unchanged.

## Update Dependency And Imports

Replace `github.com/RevoTale/no-js` with `github.com/RevoTale/no-js/v2` in
handwritten Go imports, templ imports, Go tool declarations, and module entries.
Keep GitHub repository URLs unchanged.

Before:

```go
import "github.com/RevoTale/no-js/framework/httpserver"
```

After:

```go
import "github.com/RevoTale/no-js/v2/framework/httpserver"
```

After v2.1.1 is published, pin the dependency and both tools:

```sh
go get github.com/RevoTale/no-js/v2@v2.1.1
go get -tool github.com/RevoTale/no-js/v2/cmd/no-js@v2.1.1
go get -tool github.com/RevoTale/no-js/v2/cmd/templgen@v2.1.1
```

Remove the old tool entries and any old local `replace` before these commands.
Keep the legacy module requirement until generation has replaced all old imports.

For fixture modules that intentionally replace the framework
with a checkout, the replacement's left side must also end in `/v2` and its
required version must have major version 2.

## Regenerate And Verify

Do not hand-edit generated Go. The generator now emits `/v2` imports, including
its class-list runtime helper. Keep the CLI and runtime at the same pinned tag.

```sh
task gen
go mod edit -droprequire=github.com/RevoTale/no-js
go mod tidy
task validate
task test
```

This packaging fix preserves the v2 app shape, SSR, templ, HTMX, runtime function
signatures, and configuration contracts. The performance changes do not require
component rewrites. CSS receiver methods and dynamic CSS keep upstream generation.
