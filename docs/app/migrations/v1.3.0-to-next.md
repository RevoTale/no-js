# Migrate v1.3.0 to Next: View Package, Typed System Pages, Server Error UI, Templ CSS Config, And App Shape

Applies to: upgrading from `v1.3.0` or earlier to the first release after
`v1.3.0` that includes the `web/view` package-name contract, typed generated
404 resolver contract, request-aware server error logging, optional server
error UI, default global templ CSS extraction, and strict `web/routes` and
`web/components` generation input validation.

## What Changed

- files under `web/view` must declare `package view`
- generated 404 rendering no longer calls `view.NewNotFoundView()`
- `404.templ` declares its own `view.*` model, and generation requires the
  matching `Resolve...NotFound(...)` resolver method
- `RootLayoutView` is no longer a base framework contract; keep it only if your
  app templates still use it
- `web/routes/error.templ` is no longer required or wired by route generation
- `view.NewErrorView()` is no longer a required framework contract
- default server errors log the error and return plain `Internal Server Error`
- custom 500 UI moves to `httpserver.CustomConfig.ServerErrorPage`
- advanced `framework.RuntimeContext` implementations now receive the request
  in `RespondServerError(...)`
- global templ CSS extraction is enabled by default, and the
  `no-js gen -templ-css` CLI flag is removed
- generation now rejects unrelated files under `web/routes` and
  `web/components`
- asset builds now accept `assets.browser_targets`, and explicit `web/assets`
  CSS can bundle relative CSS imports

There is no compatibility path for generated 404 constructors. Move 404 model
construction into the generated resolver method.

## Who Is Affected

You need this migration if your app currently does any of these:

- declares `web/view/*.go` as `package runtime`
- imports `web/view` with a `runtime` alias in app code or templates
- defines `func NewNotFoundView(T) RootLayoutView`
- relies on generated code to call `func NewNotFoundView() RootLayoutView`
- treats `RootLayoutView` as required by the framework instead of an app-owned
  model choice
- relies on generated code to call `func NewErrorView() RootLayoutView`
- relies on generated code to render `web/routes/error.templ`
- implements a custom `framework.RuntimeContext`
- passes `-templ-css` to `go tool no-js gen`, `go tool no-js gen assets`, or
  app-owned scripts that wrap those commands
- keeps helper Go files, docs, images, JSON/YAML data, or ignored legacy
  `error.templ` files under `web/routes`
- keeps images, fonts, downloads, docs, JSON/YAML data, or asset-only folders
  under `web/components`
- needs browser-specific CSS prefixes or JavaScript lowering beyond the default
  `es2020` output

Apps that already use `package view` and default `httpserver.NewApp(...)`
server error handling, and do not pass `-templ-css`, need fewer changes.

## Rename The `web/view` Package

Affected files:

- `web/view/*.go`
- route templates that import `web/view`
- resolver files and server entrypoints that import `web/view`

Old shape:

```go
package runtime
```

```go
runtime "example.com/your-app/web/view"
```

New shape:

```go
package view
```

```go
"example.com/your-app/web/view"
```

Update references from:

```go
runtime.NewContext()
runtime.RootLayoutView{PageTitle: "Home"}
```

to:

```go
view.NewContext()
view.RootLayoutView{PageTitle: "Home"}
```

Route templates should use the same package name:

```templ
import "example.com/your-app/web/view"

templ Page(model view.RootPageView) {
	<h1>{ model.Heading }</h1>
}
```

## Refactor 404 View Construction

Affected files:

- `web/view/*.go`
- `web/routes/404.templ`
- nested `web/routes/**/404.templ`
- `web/resolvers/*.go` when localized 404 data is needed

Old shape:

```go
func NewNotFoundView(tr frameworki18n.Context[i18n.Key]) RootLayoutView {
	return RootLayoutView{PageTitle: i18n.TUiNotFoundTitle(tr)}
}
```

Or:

```go
func NewNotFoundView() RootLayoutView {
	return RootLayoutView{PageTitle: "Not Found"}
}
```

New shape:

```templ
templ NotFound(model view.NotFoundView, path string) {
	<main>{ model.Message } { path }</main>
}
```

```go
type NotFoundView struct {
	Message string
}
```

```go
func (Resolver) ResolveRootNotFound(
	ctx context.Context,
	appCtx *view.Context,
	r *http.Request,
	notFound framework.NotFoundContext,
	params RootParams,
) (view.NotFoundView, error) {
	return view.NotFoundView{Message: "Missing"}, nil
}
```

If your 404 page needs request-scoped data such as locale, read it in the
generated resolver method:

```go
func (Resolver) ResolveRootNotFound(
	ctx context.Context,
	appCtx *view.Context,
	r *http.Request,
	notFound framework.NotFoundContext,
	params RootParams,
) (view.NotFoundView, error) {
	tr := appCtx.I18n(r)
	return view.NotFoundView{Message: i18n.TUiNotFoundHeading(tr)}, nil
}
```

Keep `Context.I18n(*http.Request)` only if resolvers or app-owned helpers still
use built-in i18n. It is not required by the minimal app contract.

Nested route-local 404 files get route-specific methods. For example,
`web/routes/_group__support/help/404.templ` generates:

```go
func (Resolver) ResolveGroupSupportHelpNotFound(
	ctx context.Context,
	appCtx *view.Context,
	r *http.Request,
	notFound framework.NotFoundContext,
	params GroupSupportHelpParams,
) (view.HelpNotFoundView, error)
```

## Remove Generated `error.templ` Usage

Affected files:

- `web/routes/error.templ`
- `web/view/*.go`
- the server entrypoint that calls `httpserver.NewApp(...)`

Old generated-route shape:

```text
web/routes/error.templ
```

```go
func NewErrorView() RootLayoutView {
	return RootLayoutView{PageTitle: "Error"}
}
```

New default shape:

```text
no web/routes/error.templ required
no view.NewErrorView required
```

With no custom server error page, `httpserver` logs the error and responds with
plain HTTP 500 text:

```text
Internal Server Error
```

If you do not need custom 500 UI, delete `web/routes/error.templ` and remove
`NewErrorView()` if it only existed for the old generated contract.

## Add Custom 500 UI Only When Needed

Affected file: the server entrypoint that calls `httpserver.NewApp(...)`.

Use `Custom Config` for app-owned 500 UI:

```go
handler, err := httpserver.NewApp(httpserver.Config[*view.Context]{
	App: generated.Bundle(appContext),
	Custom: httpserver.CustomConfig{
		ServerErrorPage: func(err error) templ.Component {
			return components.ServerError("Something went wrong")
		},
	},
})
```

Keep the custom component generic. Do not expose raw request context or the
server error to end users.

## Update Advanced Runtime Error Hooks

Affected files:

- app-owned advanced composition runtimes
- tests with custom `framework.RuntimeContext` fakes

Old shape:

```go
func (runtime *Runtime) RespondServerError(w http.ResponseWriter, err error)
```

New shape:

```go
func (runtime *Runtime) RespondServerError(w http.ResponseWriter, r *http.Request, err error)
```

Forward the request when delegating to `httpserver`.

For request-aware server error logging, prefer:

```go
Custom: httpserver.CustomConfig{
	LogServerErrorEvent: func(event httpserver.ServerErrorEvent) {
		logger.Error(
			"server error",
			"error", event.Err,
			"method", event.Method,
			"path", event.Path,
			"request_id", event.RequestID,
		)
	},
}
```

`LogServerError func(error)` still works as the legacy error-only hook when
`LogServerErrorEvent` is not set.

## Move Templ CSS Extraction To Bundle Config

Affected files:

- `no-js.bundle.yaml`
- `Taskfile.yml`, `Makefile`, CI workflows, or app scripts that call `no-js gen`
- README or deploy docs that tell developers to pass `-templ-css`

Old command shape:

```bash
go tool no-js gen -root . -templ-css
```

Or split generation:

```bash
go tool no-js gen routes -root .
go tool templgen -base . -path web/generated -path web/components -path web/view
go tool no-js gen assets -root . -templ-css
```

New default shape when the app should globalize templ `css {}` declarations:

No `assets.templ_css` setting is required. New command shape:

```bash
go tool no-js gen -root .
```

Or split generation:

```bash
go tool no-js gen routes -root .
go tool templgen -base . -path web/generated -path web/components -path web/view
go tool no-js gen assets -root .
```

If the app should keep templ CSS inline and completely disable the global
stylesheet pipeline, set `assets.templ_css` explicitly:

```yaml
version: 1

assets:
  templ_css: false
```

By default, generation scans zero-argument templ `css {}` declarations and
`web/view.TemplCSSVariants()`. If neither exists, no `styles/templ.css` asset
is emitted.

Verify the templ CSS migration with:

```bash
go tool no-js gen check -root .
```

If your app expects a global templ stylesheet, also verify the generated
manifest has a `styles/templ.css` entry after asset generation:

```bash
grep 'styles/templ.css' web/assets-build/manifest.json
```

## Clean Route And Component Trees

Affected files:

- `web/routes/**`
- `web/components/**`

`web/routes` is now validated as a route-generation input tree. Keep only
route templates, route convention Go files, and same-stem root/page/layout/404
Client Assets there. A route Client Asset must have the matching template in
the same directory.

Old route shapes that now fail:

```text
web/routes/helper.go
web/routes/README.md
web/routes/logo.svg
web/routes/default.css
web/routes/error.templ
```

New route shape:

```text
web/routes/root.templ
web/routes/root.css
web/routes/404.templ
web/routes/page.templ
web/routes/page.css
web/routes/page.ts
web/routes/api/ping/route.go
```

Move route helper code to `web/resolvers`, `web/view`, or another app-owned
package outside `web/routes`. Move static files to `web/assets` or
`web/public`. Delete `web/routes/error.templ`; custom 500 UI now belongs in
`httpserver.CustomConfig.ServerErrorPage`.

`web/components` is now validated as a component package tree. Each component
must live in `web/components/<name>/` and contain `<name>.templ` or
`<name>.go`. Handwritten `.templ` files and component CSS/JS/TS must use the
component stem. Support `.go` files are allowed, but exported Go API belongs in
`<name>.go`.

Move root-level component files into component package directories:

```text
# old
web/components/profile.templ

# new
web/components/profile/profile.templ
```

Split extra templates into separate component packages instead of keeping more
than one handwritten `.templ` file in one package:

```text
# old
web/components/card/card.templ
web/components/card/header.templ

# new, sibling component
web/components/card/card.templ
web/components/card_header/card_header.templ

# or new, nested component
web/components/card/card.templ
web/components/card/header/header.templ
```

Keep public Go declarations in the anchor Go file:

```go
// old: web/components/card/helpers.go
package card

func RootClass() string { return "card" }
```

```go
// new option A: web/components/card/card.go
package card

func RootClass() string { return "card" }
```

```go
// new option B: web/components/card/helpers.go
package card

func rootClass() string { return "card" }
```

Component assets must be same-stem with the package anchor. Choose only one script source extension per component because they all emit `<name>.js`:

```text
# old
web/components/card/theme.css
web/components/card/behavior.ts

# new
web/components/card/card.css
web/components/card/card.ts
web/components/card/card.tsx     # alternative to card.ts; choose one script source
```

Move non-component files out of the tree:

```text
# old
web/components/card/logo.svg
web/components/card/README.md
web/components/card/data.json

# new
web/assets/card/logo.svg
web/public/card/README.md
web/view/card_data.go
```

Verify the app shape with:

```bash
go tool no-js gen routes -root .
```

## Configure Browser Targets When Needed

Affected file: `no-js.bundle.yaml`.

No migration is required for apps that are happy with the default `es2020`
asset output. If the app needs browser-specific prefixes or syntax lowering,
add `assets.browser_targets`:

```yaml
version: 1

assets:
  browser_targets:
    - es2020
    - chrome107
    - firefox104
    - safari16
```

The same target list applies to Client Asset scripts, generated global templ
CSS, generated route/component CSS, and explicit `web/assets` CSS and
JavaScript. Empty target entries fail config resolution.

Explicit CSS under `web/assets` can now bundle relative CSS imports:

```css
@import "./reset.css";
```

Do not use CSS imports for route/component asset discovery. Route and component
CSS still belongs beside the owning template or component package.

## Verify The Migration

Run generation and tests from the app root:

```bash
go tool no-js gen -root .
go test ./...
```

Your app is migrated when:

- all non-test files under `web/view` use `package view`
- imports of the app view package are unaliased unless there is a documented
  versioned import-path exception
- `404.templ` uses an app-owned `view.*` model type
- `web/resolvers` implements each generated `Resolve...NotFound(...)` method
- `RootLayoutView` remains only if your app templates still use it
- `web/routes/error.templ` is not needed for generation
- any custom 500 UI is configured through `httpserver.CustomConfig.ServerErrorPage`
- custom runtime implementations use `RespondServerError(w, r, err)`
- scripts and docs no longer pass `-templ-css` to `go tool no-js gen`
- `web/routes` contains only route templates, route convention Go files, and
  same-stem page/layout/404 Client Assets
- `web/components` contains only component package files, component Client
  Assets, and generated helper files
- apps that need global templ CSS omit `assets.templ_css` or leave it set to
  `true`; apps that want inline templ CSS set `assets.templ_css: false`
- apps that need browser-specific output set `assets.browser_targets`; other
  apps keep the default `es2020` behavior
